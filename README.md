# 时光 · 时间手记

中文、手机优先的时间管理网页。前端是原生 HTML / CSS / JavaScript，无第三方依赖；可选 Python 标准库 + SQLite 服务用于多设备共用数据。

## 开始使用

**这台 Windows 电脑：双击 `启动时光.cmd`。** 脚本会自动寻找已安装的 Python，启动服务并打开网页。

1. 在「今日记录」填写“刚刚做了什么”。首次发送时设置今天的起点。
2. 后续发送自动记录“上一条结束 → 此次发送”的时间。
3. 忘记发送时，点击「手动补录」或时间线空档的「补录」。
4. 手机与电脑连接同一 Wi-Fi，在「数据与设置 → 手机连接方式」找到手机地址。
5. 电脑需保持运行。关闭启动窗口会停止服务，数据仍保留。

第一次连接可能需要在 Windows 防火墙中允许 Python 访问**专用网络**。连接地址含随机访问码，只供自己的设备使用。局域网版本使用 HTTP，适合可信的家庭网络，不要直接暴露到公网。

**纯网页使用：** 直接打开 `dist/index.html`。这种方式数据只在该浏览器中保存，不会自动同步。也可把整个 `dist` 文件夹上传到任意静态托管平台；静态部署依然是每个浏览器独立保存。清除浏览器数据、换浏览器或换网址之前，请导出 JSON 备份。

## 四个功能

- **消息记时**：连续消息自动记时、每日独立起点、手动补录与编辑、空档显示；覆盖补录仅替换指定时间，保留原记录前后片段。自动分类可手动覆盖。
- **统一总表**：按关键词、分类、日期筛选、分页，导出含中文表头的 UTF-8 CSV（Excel 可读取）。
- **时间洞察**：查询过去 1–366 天的关键词投入，折线图、柱状图、累计时长、每日平均、投入天数、单日最高、每日明细与统计 CSV。
- **待办日历**：月历选日期、添加/编辑/删除待办、完成标记、导出标准 `.ics` 文件。按当前需求仅使用内置日历，无第三方账号依赖。

额外提供完整 JSON 备份/恢复、独立演示模式、桌面与手机布局。演示数据不会写入真实数据库。

## 记时与统计规则

- 所有页面按 **北京时间 Asia/Shanghai（UTC+8）** 显示，底层保存毫秒时间戳。
- 每天首次消息需要确认起点，不会擅自把昨天到今天的整晚归入当前事项。跨午夜的实际活动可以在补录中指定。
- 文本是事项描述，**不会自动解析自然语言中的时间**。例如补录“昨天 9 点读书”时，需要在补录表单选择日期和时间。
- 时间线展示当天零点至当前时刻的记录及空档；空档不算活动时长。
- 所有实际记录不允许重叠。覆盖时需勾选确认；冲突片段可被拆成前后两条。
- 已录入时间可以精确到秒，页面简化显示至分钟；不足一分钟会明确标记。
- N 天包含截至当天。日均 = 范围内总时长 ÷ N，零记录日也参与计算。额外给出“有投入日的日均”。
- 跨天记录按与每个自然日的交集统计；总表日期筛选匹配相交记录，总时长只计算日期内部分，而表格及导出保留完整原始记录。
- 完成待办不会自动计入实际用时；未来计划需要用户做完后通过消息记录。
- 当前不提供系统推送、后台提醒或第三方日历双向同步。

## 本地服务

需要 Python 3.10+，不需要 pip 安装任何库：

```sh
python server.py --lan --open
```

只在本机使用：

```sh
python server.py --open
```

自定义端口与数据目录：

```sh
python server.py --port 8766 --data-dir ./my-data --lan
```

Windows 脚本也支持 `./start.ps1 -Port 8766 -LocalOnly -NoOpen`。

服务数据保存在 `.data/shiguang.sqlite3`，随机访问码保存在 `.data/access.key`。每天首次启动会在 `.data/backups/YYYY-MM-DD.sqlite3` 创建数据库快照；运行期间新增记录不在当天启动快照内，因此仍建议定期在网页导出 JSON。完整搬迁建议停止服务后复制整个 `.data` 文件夹，保留 SQLite 可能产生的辅助文件。

每次写入校验数据并通过 SQLite 事务原子保存，使用 revision 检查防止两个设备相互覆盖。检测到并发冲突时刷新数据，保留输入，请用户再次保存。离线时不会假装保存成功。页面可在返回前台、聚焦和每 30 秒读取服务端新数据。

纯网页模式使用 localStorage，多个同源标签页通过存储事件更新，在浏览器支持时使用 Web Locks 保护并发写入。HTTP 局域网访问通常不支持安装式 PWA/Service Worker；HTTPS 静态托管与 localhost 支持离线页面缓存。服务模式离线时不能读写数据库。

## 部署状态

此目录包含可运行版本和可独立部署的静态文件。在线 Sites 注册尝试因连接错误失败，核查站点列表为空，**尚未发布到公网，也没有已部署网址**。不依赖在线托管即可使用上述两种运行方式。

如未来需要任意网络访问、多账号和云同步，可把 Python 服务部署在具有持久化磁盘的主机，并配置 HTTPS 反向代理和访问控制。当前访问码仅面向个人局域网，不能代替完整多用户账号系统。
